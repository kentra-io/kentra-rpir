# A mod Button with `action` naming an engine keybinding action lets a user's chord open/toggle the pane from the prompt while the pane is closed — i.e. a global hotkey for the pane is achievable (for example via an always-mounted AbovePrompt band button bound to an otherwise-unhandled engine action), or else no hotkey is possible and /rpir-graph is the only toggle

Verdict: verified (confidence: high)

Evidence: docs: /private/tmp/claude-501/bundled-skills/2.1.301/3455b09f838254e0de91fd73a4243b8b/plugin-authoring/types/claude-code.d.ts@2.1.301 (ButtonProps.action, line ~1119) and reference.md line 158

The mod API bundled with Claude Code 2.1.301 states the mechanism directly. `ButtonProps.action` reads: "An engine keybinding action (`"app:cycleDiffBase"`) whose chord, as the person bound it, presses this from the prompt; unknown names refused. Chords, or a modified key Global or an active context binds, on the terminal while mounted, no dialog up and no engine handler of the action mounted; a pane's over the band's over another's, then the last drawn." reference.md (line 158) repeats it: "a Button naming one of the engine's keybinding actions is also pressed by the person's chord for it from the prompt while it is mounted: chords, or a modified key Global or an active context binds, and not while an engine handler of that action is mounted." Press raises `ui.press` (its `onPress`), so the handler can open the pane. Consequences for the pane: (1) the Button must be mounted, so a global hotkey needs an always-mounted AbovePrompt band that renders a Button (it may be one-glyph or tiny; the pane being closed does not matter, only the band being mounted); (2) the action must be one no engine handler currently holds, otherwise the engine handler wins (and only chords or modified keys that Global or an active context binds count, so a bare letter does not work); (3) the chord is "as the person bound it", so the user's ~/.claude/keybindings.json governs, and remapping the borrowed action to a chosen chord is the user-side way to get the pane chord; the plugin cannot pick a chord of its own; (4) refused when a dialog is up. The Button `hotkey` prop is a different, weaker route: it only works while the band/pane holds focus (after ctrl+x tab, click or open focus), not from the composer. Fallback if the band approach proves undesirable: /rpir-graph remains the toggle.

Gaps:
- Which engine actions are unhandled while the prompt is focused (safe to borrow) is not listed in the types or reference.md; only `app:cycleDiffBase` appears as an example, and whether it has a mounted handler in normal prompt state was not checked. A spike (or the keybindings docs list of actions) is needed to pick the action.
- Whether an always-mounted band can render a visually empty or minimal Button (so the pane is not cluttered) was not checked; run no code was required here.
- The user-facing keybindings.json step (binding a chord to the borrowed action) was inferred from "as the person bound it", not shown in a worked example; default chord of the chosen action matters if the user has not rebound it.
