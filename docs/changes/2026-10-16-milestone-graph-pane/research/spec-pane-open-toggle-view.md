# A mod can open a docked side pane in the terminal via $.ui.open, toggle it from a plugin slash command, open it unasked when a run starts, redraw it on a timer or state change, and its keyed Buttons are keyboard-selectable with Enter opening a subagent's transcript via $.ui.view({agentId})

Verdict: verified (confidence: high)

Evidence: docs: plugin-authoring/types/claude-code.d.ts@2.1.301 (bundled at /private/tmp/claude-501/bundled-skills/2.1.301/3455b09f838254e0de91fd73a4243b8b/plugin-authoring/types/claude-code.d.ts)

The 2.1.301 mod typings (primary source for this build) state every part directly. `$.ui.open({id,title,focus,closeOnEscape,holdToasts,rows,columns})` opens a Pane; "Asked ... a pane is placed at any width: docked beside a fullscreen transcript from 110 columns, else inline above the prompt. Unasked it is placed from 144 terminal columns (110 for an id the person opened from this plugin before ... and has not closed by hand since) and waits undrawn below that, no `ui.render` raised". Asked excludes "a timer, `session.start`, a queued prompt, nor `focus`", so an open from session.start or from a run start is unasked (144 floor), while a plugin slash command's `command.run` hook is asked (110 floor, or inline above the prompt in the non-fullscreen layout). The shipped example `examples/pane.tsx` does exactly this: registers a command at `session.start`, `void $.ui.open(...)` there, and `$.ui.open` again in `on('command.run', {command})`. `Pane` props carry `placement: 'dock' | 'inline'` ("the terminal in fullscreen from 110 columns"); docking only exists in the fullscreen layout, the main screen is always inline (`CommandPresentation.isFullscreen`, `e.viewport.isFullscreen`). `$.ui.close({id})` and `$.ui.panes()` (isPlaced) allow a real toggle. Redraw: `$.ui.invalidate("ui.render")` redraws shown panes, "ten a second at most, thirty in the terminal for a shown pane"; state-change redraw is via atoms/`update` as in the example, and a timer can call invalidate (no timer API documented, ordinary JS timers in the module are assumed). Buttons: "a click, a `hotkey`, the chord for its `action`, or Enter under the focus raises `ui.press`, its bottom `onPress`"; a pane opened with `focus` takes the keys, Tab and arrows walk its buttons (reference.md). `$.ui.view({agentId})` is present on 2.1.301: "Puts an agent's transcript in the main view ... Only while the call answers the person's own input (a press, a pick, their prompt or command)"; agentId is the `id` from `$.agent.list()` and `{}` returns to main; example `onPress: () => $.ui.view({ agentId: agent.id })`. So it works from a Button press but not from a timer or event hook. Implications for the spec: an unasked open at run start only appears in a fullscreen terminal at least 144 columns wide, otherwise it waits undrawn, so the slash command is the reliable fallback; the Button's focus requires the person to give the pane the keyboard (ctrl+x tab, or opened with `focus`, which itself counts as unasked); mapping a milestone to an agentId needs `$.agent.list()` or tool.call/turn events (the implementer prompt's first line "You are implementing milestone M{{number}}" is usable for matching but was not exercised).
