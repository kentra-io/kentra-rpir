# A marketplace-installed Claude Code plugin that already ships skills, agents and workflows can also ship a hooks module (hooks/hooks.json with modules) and it loads as a mod for users who install the plugin from a marketplace, on Claude Code >= 2.1.287

Verdict: verified (confidence: high)

Evidence: docs: https://code.claude.com/docs/en/plugins/mods/overview (current docs; text says "Claude Code v2.1.287 or later")

The official mods docs state this directly. A mod is "a plugin directory" with `.claude-plugin/plugin.json` ("Mods add no required fields") plus `hooks/hooks.json` holding `"modules": ["./register.js"]` (one path, relative to hooks.json) and the hooks module exporting `register(on, options)`. Overview: "A mod installs as a plugin, from a marketplace ... `/plugin install token-chart@your-org` / `claude plugin install token-chart@your-org`", and "[Install plugins] covers marketplaces, scopes ... and keeping plugins updated, all of which apply to a plugin that contains a mod without changes." Mixed plugins are explicit: "A plugin can hold all of them, so a mod can ship in the same plugin as a skill and an MCP server." Other docs lines confirm the skills stay independent of the mod: `disableAllHooks` / `allowManagedModsOnly` "stop a mod and leave the rest of its plugin in place: the plugin stays installed, and its skills, commands, agents, and MCP servers load." hooks.json "can also hold settings hooks under `hooks`", so adding it to kentra-rpir does not conflict with the existing `skills/`, `agents/` and `workflows/` directories (the manifest's `hooks` key merges with `hooks/hooks.json`; `workflows/` is a separate standard location). Mods are on by default; "In the terminal, use Claude Code v2.1.287 or later" (Desktop from 2.1.286); v2.1.287+ ignores `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS`. The bundled plugin-authoring reference for 2.1.301 (the local build) says the same: a user adds a marketplace (`y`), picks a scope, and for a hooks-module plugin sees "Installed <mod>. Plugin is now active.", hooks running "in that session from then on with no reload", and under user scope in later sessions. Trust and enable prompts: there is no mod-specific consent prompt beyond the normal plugin install flow (marketplace add question, scope choice) and a warning that mods run with the user's permissions. An untrusted directory's trust prompt applies to project-scope loading ("No mod loads in a directory you opened for the first time: You haven't answered the trust prompt"). Installed mods share one worker thread; a broken module or hook is skipped and the session continues, and installed-plugin edits require a new version/commit plus `claude plugin update` then `/reload-plugins` (plugin.json `version` 0.4.1 pins updates, so bump it with the mod). Ways a mod can silently not load for a user: `disableAllHooks`, `allowManagedHooksOnly`, `allowManagedModsOnly`, `--bare`, `--safe-mode`, Anthropic's remote rollout switch, a same-named enabled plugin, and `claude -p` / cloud sessions (hooks run, nothing draws, so a pane would not appear there). Drawing a Pane works in terminal and Desktop (VS Code from extension 2.1.299). Diagnose with `claude plugin test` (from a non-mod directory) and `claude --debug` (installed-mod load failures appear only in the debug log).

Gaps:
- Behaviour of Claude Code older than 2.1.287 on a plugin with hooks/hooks.json `modules`: docs say only that mods need 2.1.287+ (and that `options` on userConfig breaks load before 2.1.271); whether older builds silently ignore the unknown `modules` key or error on hooks.json was not stated and no source was checked. Skills/agents/workflows should be unaffected but this is not confirmed. The plugin manifest could be tested on an old build.
- No Claude Code source for 2.1.301 was inspected beyond the bundled plugin-authoring reference; findings rest on the official docs (which describe v2.1.290-2.1.300 features) and that reference.
- Not tested end to end: no throwaway mod was built or loaded (run no code was the brief), and no marketplace install of kentra-rpir with a hooks module was observed.
- Docs mention a Anthropic-side remote "rollout switch" that can turn installed mods off; its current state and any future change cannot be verified.
- Field reports not searched.
