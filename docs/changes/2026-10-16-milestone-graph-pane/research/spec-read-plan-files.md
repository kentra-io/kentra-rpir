# A mod can read files in the project (plan.yaml, .kentra-rpir/sessions.map) and learn the current session id, either via $.fs or by running a binary such as `milestoned-plan-dag resolve <plan>` via $.process.run and parsing its stdout, without Node APIs

Verdict: verified (confidence: high)

Evidence: docs: /private/tmp/claude-501/bundled-skills/2.1.301/3455b09f838254e0de91fd73a4243b8b/plugin-authoring/types/claude-code.d.ts@2.1.301 (`$.fs.read`, `$.process.run`, `$.session.id`)

Verified from the mod API typings shipped with Claude Code 2.1.301 (read only; no code run). `$.fs` is "the file system as the engine's own process reaches it; a relative path is under the session's working directory, and text is UTF-8", with `read(path)` returning text (rejects if missing or over 4 MiB), plus `list`, `exists`, `stat`, `write`. Absolute paths are used as given; "where one may go is an `fs.*` hook's to say", so only another plugin's hook can restrict it, and no user permission prompt is documented. `$.process.run(argv, {cwd, env, stdin, timeoutMs})` runs a host command by argv (no shell, "CLI only", "run as the user the session runs as"), resolves `{exitCode, stdout, stderr}` for any exit code, with stdout capped at 4 MiB, default timeout 30 s, max ten minutes; so `["milestoned-plan-dag","resolve","<plan>"]` works if the binary is on the PATH the host process has, and the YAML stdout comes back as a string. `$.session.id()` returns "the session's id (the transcript file's name)" as a Promise<string>; `session.end` events also carry `sessionId`, and after `/clear` or resume the id changes (no `session.start` after /clear), so the mod must re-read `$.session.id()` rather than cache it. Parsing: the module environment has "no DOM and no Node", no `eval`/`new Function`/WebAssembly, and `import()` makes a module fail to load; but a module may `import` other files of the plugin (.ts/.js/.mjs etc.), so a hand-written or pre-bundled pure-JS YAML parser shipped inside the plugin is allowed in principle. The resolve output shape (schemaVersion, order, milestones[{number, slug, goal, depends_on}]) is simple enough for a small purpose-built parser, and sessions.map is read the same way via `$.fs.read`. A mod can also shell out to a binary for anything needing compiled code.
