# A mod can see each running subagent's tool calls (tool name and input, e.g. Bash command) with that subagent's agent id, and the main session's Bash tool calls and their results, so it can show the current tool per milestone and detect `git merge --no-ff ... -m "Merge M<n> ..."` in the main session

Verdict: verified (confidence: high)

Evidence: docs: /private/tmp/claude-501/bundled-skills/2.1.301/3455b09f838254e0de91fd73a4243b8b/plugin-authoring/types/claude-code.d.ts@2.1.301 (ToolCallInput, ToolCallEnvelope, ToolCallResult, AgentLoop)

The mod API typings shipped with Claude Code 2.1.301 state the behaviour directly. `tool.call` "Fires when the engine is about to run a tool" and its input `ToolCallInput = ToolCallEnvelope & AgentLoop & ToolRequestMeta` is documented as "the tool, the id of this call, the tool's arguments beside them (`e.command` for Bash), and `agentId` in a subagent". `AgentLoop.agentId` is "the loop's agent id inside a subagent's or a teammate's loop, absent on the main loop", and it is the same id `$.agent.list()` and the Agent tool's record (`agentId`) use. So a `tool.call` hook sees every tool call of every subagent loop with tool name, input and agent id, and the main loop's calls with no agentId. Result access: `next(e)` in a `tool.call` hook "resolve[s] to the tool's result (`{ result, context? }`) or `{ deny }`", from core `{ ref, result, text }` plus `isError`; the built-in Bash result type is `{ stdout, stderr }` (BuiltinToolResults example). A hook can therefore call `next(e)`, then inspect `e.command` (match `git merge --no-ff ... -m "Merge M<n> ..."`) and the result (exit or error via `isError`, `stdout`) on the main loop (agentId undefined). Classic hooks (`classic.PreToolUse`, `PostToolUse`, `SubagentStart`/`SubagentStop` with `agent_id`) are also available as an alternative. Mapping an agentId to a milestone: the main session's Agent tool call carries the prompt whose first line is `You are implementing|verifying milestone M{{number}} ...`; the agentId comes from the Agent call's result record, or from `agent.spawn`/SubagentStart events (not read in detail), so the mod can learn the milestone-to-agent mapping from the dispatching Agent call. The "current tool per milestone" is the latest `tool.call` per agentId. Caveats: a `tool.call` hook is a gating site (a hook that throws is skipped unless given a `.catch`; an observer should call `next(e)` and never deny); `tool.call` fires before the tool runs, so a merge's success must be read from the `next(e)` result, not assumed.
